# Namespace `clore::net`

## Summary

The `clore::net` namespace provides the networking and protocol layer for interacting with large language model (LLM) providers. It defines the core data types for constructing completion requests and processing responses, including message types (`SystemMessage`, `UserMessage`, `AssistantMessage`, `ToolResultMessage`, `AssistantToolCallMessage`), tool-‑related structures (`FunctionToolDefinition`, `ToolCall`, `ToolOutput`, `ToolChoice` variants), output contracts (`PromptOutputContract`), and error handling (`LLMError`). The namespace also supplies asynchronous entry points such as `call_llm_async`, `call_completion_async`, and `call_structured_async`, which coordinate request submission, rate‑limiting (via `initialize_llm_rate_limit` and `shutdown_llm_rate_limit`), and capability‑aware request adaptation.

Architecturally, `clore::net` hides the details of provider‑specific communication and offers a unified interface for managing LLM interactions. It includes utilities for probing and caching provider capabilities (`get_probed_capabilities`, `sanitize_request_for_capabilities`), for recognizing and extracting feature‑rejection errors (`is_feature_rejection_error`, `parse_rejected_feature_from_error`), and for validating the runtime environment (`validate_llm_provider_environment`). Together, these components form a robust foundation that higher‑level application code uses to send prompts, handle structured tool calls, and process completions without needing to manage raw network protocols or provider idiosyncrasies.
